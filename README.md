# Агент-помощник по типовому договору

Инструмент сравнивает договоры, которые институты сделали на базе типового
(исходного варианта на согласование), находит **общие паттерны** — правки, которые
несколько институтов внесли независимо друг от друга, — и предлагает, как поправить
типовой договор к следующему кругу согласования.

Идея простая: если пять институтов из шести дописали антикоррупционную оговорку
и сократили срок оплаты, то это не их фантазия, а пробел в эталоне.

## Что делает агент

1. **Читает документы** — `.docx` (без внешних зависимостей), `.txt`, `.md`,
   `.pdf` (если есть `pdfplumber` / `pypdf` / `pdftotext`).
2. **Разбирает договор на пункты** — по нумерации (`2.1.`, `4.3.`) и заголовкам разделов.
3. **Сопоставляет каждый договор института с эталоном** — по номеру пункта и по
   схожести текста (TF-IDF + совпадение 3-грамм), и классифицирует расхождения:
   новый пункт / переформулирован / исключён / без изменений.
4. **Группирует правки разных институтов в паттерны** — похожие правки собираются
   в один кластер; тема кластера определяется по юридическим маркерам
   (НДС, неустойка, конфиденциальность, персональные данные, ЭДО, ИС и т. д.).
5. **Выдаёт рекомендации** — что добавить, что переформулировать, что убрать;
   с частотой («3 из 3 институтов»), приоритетом, дословно совпадающими
   формулировками и готовой редакцией пункта.
6. **Опционально подключает Claude** (`--llm`) — модель пишет человеческое пояснение,
   нейтральную редакцию пункта и предупреждение о риске.

Без `--llm` агент работает полностью офлайн, только на стандартной библиотеке Python.

## Запуск

```bash
# отчёт в stdout
python3 -m contract_patterns -b эталон.docx институт_1.docx институт_2.docx институт_3.docx

# каталог со всеми договорами институтов + файлы отчёта
python3 -m contract_patterns \
    --baseline contracts/эталон.docx \
    contracts/институты/ \
    --out отчет.md --json отчет.json

# с формулировками от Claude
export ANTHROPIC_API_KEY=...
python3 -m contract_patterns -b эталон.docx институты/ --llm --out отчет.md
```

| Флаг | Назначение |
| --- | --- |
| `-b, --baseline` | исходный вариант договора на согласование (эталон) |
| `--out` | файл Markdown-отчёта (по умолчанию — вывод в терминал) |
| `--json` | машиночитаемый отчёт для дашборда или дальнейшей обработки |
| `--min-support` | сколько институтов должны внести правку, чтобы она считалась общей (по умолчанию `max(2, N/3)`) |
| `--llm` | добавить пояснения и редакции от Claude (нужен `ANTHROPIC_API_KEY`) |
| `--model` | модель Claude, по умолчанию `claude-opus-5` |

## Пример

В каталоге `examples/` лежат эталон и три договора «институтов», а также
готовый отчёт `report_example.md`. Прогон:

```bash
python3 -m contract_patterns -b examples/baseline.txt examples/ -o examples/report_example.md
```

находит 8 общих паттернов, из них 6 — у всех трёх институтов: антикоррупционная
оговорка, конфиденциальность, персональные данные, ЭДО с УКЭП, оговорка про НДС
при УСН и потолок неустойки.

## Как использовать в работе

1. Складывайте подписанные договоры институтов в один каталог.
2. Раз в квартал (или перед новой редакцией типового договора) запускайте агента.
3. Смотрите паттерны с приоритетом «высокий» — это то, что институты правят всегда;
   их выгоднее сразу включить в типовой договор, чтобы не согласовывать по кругу.
4. Паттерны «средний» — кандидаты в опциональные блоки или в комментарии к эталону.

## Программный интерфейс

```python
from contract_patterns.agent import analyze
from contract_patterns.report import to_markdown

result = analyze("эталон.docx", ["и1.docx", "и2.docx", "и3.docx"], min_support=2)
for rec in result.recommendations:
    print(rec.support, rec.title, rec.action)

print(to_markdown(result.baseline, result.revisions, result.changes,
                  result.recommendations, result.min_support))
```

## Структура

| Модуль | Ответственность |
| --- | --- |
| `extract.py` | чтение .docx/.txt/.pdf/.doc в абзацы |
| `clauses.py` | разбор на пункты, нормализация текста |
| `similarity.py` | TF-IDF, косинус, n-граммы |
| `compare.py` | сопоставление договора института с эталоном |
| `cluster.py` | группировка правок в общие паттерны |
| `topics.py` | юридические темы пунктов |
| `recommend.py` | формулировка рекомендаций |
| `llm.py` | необязательный слой Claude |
| `report.py` | Markdown и JSON отчёты |
| `agent.py`, `cli.py` | пайплайн и командная строка |

## Ограничения, о которых стоит знать

- Агент считает паттерном совпадение формулировок, а не юридического смысла:
  две разные по сути правки с похожими словами могут попасть в один кластер.
  Поэтому в отчёте всегда показаны исходные редакции институтов — проверяйте.
- Чисто числовые правки (суммы, номера, реквизиты) намеренно игнорируются как
  «заполнение бланка»; правка вида «30 календарных → 15 рабочих дней» учитывается,
  потому что меняется не только число.
- Сканы без текстового слоя агент не прочитает — нужен OCR до запуска.
- Решение о правке типового договора принимает юрист: агент даёт статистику и
  черновую редакцию, а не согласовывает текст.
